# 互斥量、优先级继承与临界区粒度(任务间通信上篇之二)

> 一句话定位:**互斥量是"保护共享资源"的锁** —— 多个任务要动同一份东西(串口、LED、共享变量)时,靠它保证"一次只有一个在动"。
>
> 兄弟篇:《队列、生产者-消费者与拷贝语义》讲的是"**传**数据"。两者不是竞争关系,是两个正交的工具。
>
> 再往深一层:优先级翻转、优先级继承、优先级天花板、互斥量与二值信号量的区别,另见《优先级翻转、优先级继承、优先级天花板、互斥量与二值信号量的区别》。

---

## 1. 为什么需要:你的 printf 交错问题

`printf("111\r\n")` 是**逐字符**经 fputc 输出,每发 1 个字符要等 TXE(约 87µs@115200)。两个任务同时在打印,1ms 的 tick 可能打断在**任意两个字符之间**,于是:

- 两行字符互相穿插(切碎);
- 更糟:task A 查完 TXE 被打断,task B 写完 DR,A 恢复后再写 DR → **B 的字符被覆盖丢掉**(USART 的 DR 一次只能存 1 个待发字节)。

**锁的粒度必须 = "一整行打印"的原子单位。** 锁在 fputc 里(每字符加锁)没用 —— 行与行照样穿插;锁要包住整个 printf 调用。

## 2. 你的 print_line(api/debug.c 对照)

```c
// api/debug.c
static SemaphoreHandle_t print_mutex = NULL;   // static:只有本文件拿得到,外部想绕开锁都没门

void debug_init(void)                          // 必须在 vTaskStartScheduler() 之前调用
{
    print_mutex = xSemaphoreCreateMutex();     // 从 heap 分配,所以要在调度器起来之前
}

void print_line(const char *s)
{
#if PRINT_LOCK_ENABLED
    xSemaphoreTake(print_mutex, portMAX_DELAY); // 拿锁;拿不到就睡,不用轮询空耗
    printf("%s\r\n", s);                        // 临界区:一整行原子
    xSemaphoreGive(print_mutex);                // 放锁(必须!漏掉 = 所有等锁任务永久阻塞)
#else
    printf("%s\r\n", s);                        // 无锁对照组
#endif
}
```

**它为什么在 `api/debug.c` 而不在 `user/main.c`**:串口是**全局共享资源**,不只 print_task1/print_task2 在用,`api/usart1.c` 的串口接收任务也要回显。放在 debug.c 里,谁想打印就包含 `debug.h`,不必反过来依赖 main.c。

## 3. 铁律

1. **Take/Give 严格配对**,而且**谁 Take 的谁 Give**(互斥量有"所有权"——这是它和二值信号量最大的区别)。
2. **创建必须在调度器启动前**(从堆分配)。
3. **中断里别碰互斥量**:Take 可能阻塞,ISR 不允许;共享资源若被中断和任务共用,用临界区(taskENTER_CRITICAL)而不是互斥量。
4. **持锁时间越短越好**,锁里别干耗时的活(否则所有等锁任务都陪你耗)。

---

## 4. 为什么要 `xSemaphoreCreateMutex()` 而不是二值信号量当锁:**优先级继承**

先看灾难(优先级反转):task2(优先级 4)在等锁,锁被 task1(优先级 2)拿着;此时 task1 还没跑完,优先级 3 的 led_task 醒来 —— **3 > 2,task1 被 led_task 抢占**,它手里的锁迟迟放不掉 → 优先级 4 的 task2 被优先级 3 的 led_task 间接饿死。高优先级任务输给了中优先级任务,荒谬。

互斥量内置解法:**task2 等锁 → task1 被临时提升到 4** → led_task(3)再也抢不动 task1 → task1 快速打完放锁 → task1 降回 2,task2 拿到锁继续。

二值信号量没有所有权也没有继承,拿来当锁就会出现上面的反转。**所以:当锁 → 永远 `xSemaphoreCreateMutex`。**

## 5. 坑清单

| 坑 | 后果 |
|---|---|
| Take 了忘 Give(比如某分支提前 return) | 死锁:所有等锁任务永久 Blocked,系统"假死" |
| 持锁任务自己又 Take 同一把锁 | 自己等自己,死锁(要用 `xSemaphoreCreateRecursiveMutex` 递归互斥量) |
| 两个任务互拿对方的锁 | 经典死锁(ABBA),设计时避免嵌套拿锁 |
| 锁粒度太小(fputc 里加锁) | 看似互斥,行照样穿插 |
| 把优先级继承当万能 | 继承只在"等锁"瞬间生效,不等锁就没有 |

## 6. 选型:什么时候用哪个

| 场景 | 用 |
|---|---|
| A 任务要把**数据/事件**交给 B 任务 | 队列(或任务通知) |
| 多个任务共用**同一份资源**,防止互相踩 | 互斥量 |
| 保护**中断和任务**共享的资源 | 临界区(不是互斥量) |
| 只喊一嗓子"有事了",不带数据 | 二值信号量 |
| 攒 N 件事 / 池化 N 个资源 | 计数信号量 |

判断口诀:**传数据吗?传 → 队列。不传数据、只是防踩踏 → 互斥量。**

队列和互斥量不是竞争关系,是**两个正交工具**:队列解决"我怎么把消息给你",互斥量解决"咱俩别同时碰它"。你的 key 模块用队列送按键事件,打印用互斥量护串口 —— 两个都用上了,各管各的。

> 队列那一侧怎么用、有哪些坑,见《队列、生产者-消费者与拷贝语义》。

## 7. 验证实验:怎么证明互斥量在起作用

核心认知:**竞争要先造得出来,锁才有东西可锁。**

- 低优先级任务打印时,高优先级任务恰好醒来,才能"拦腰打断";
- 每行字符数必须 > 12(≈1ms,跨得过 tick 边界)才可能被打断。

工程里已经备好两个开关,不用手改代码:

| 开关 | 位置 | 作用 |
|---|---|---|
| `PRINT_STRESS_ENABLED` | `user/main.c` | 1 = 制造竞争:print_task1(优先级 2)去掉 `vTaskDelay`,死循环狂打;print_task2(优先级 4)改成每 100ms 插一次话 |
| `PRINT_LOCK_ENABLED` | `api/debug.c` | 1 = 加锁;0 = **无锁对照组**(`print_line` 里那对 Take/Give 被条件编译掉) |

实验步骤:

1. 把 `user/main.c` 两个任务里那句 `print_line(...)` 的注释取消掉(平时是注释着的,免得串口被刷屏)
2. `PRINT_STRESS_ENABLED` 置 **1**
3. `PRINT_LOCK_ENABLED` 置 **0** 烧一轮 → 预期 111 的句子被 222 拦腰截断,出现畸形行/混行
4. **只把 `PRINT_LOCK_ENABLED` 改成 1** 再烧一轮 → 每行完整不穿插

两轮之间只改这一个值,其余全不动,才是干净对照。

⚠️ 用串口工具时别用中文测试内容:UTF-8 中文 3 字节,监视器按块读取,块边界切在汉字中间就显示 `�`——那是**显示端问题,不是互斥失效**。实验内容一律纯 ASCII。

⚠️ 优先级 2 vs 4、周期 500/1000ms 且相位对齐时,两个任务**永远排着队打**,根本不会竞争 → 无锁也"看起来干净",验证不了任何东西。竞争窗口要靠"低优先级长工 + 高优先级定期插话"造出来 —— 这正是 `PRINT_STRESS_ENABLED` 干的事。

## 8. 自测

**Q1.** 互斥量和二值信号量都只能记 0/1,为什么锁必须用互斥量?

<details>
<summary>答案</summary>

互斥量有**所有权 + 优先级继承**:持有者被高优先级任务等锁时临时升频,快速释放;二值信号量没有,会出现"高优先级被中优先级饿死"的优先级反转。

</details>

---

**Q2.** `print_line` 里如果忘了 `xSemaphoreGive`,会观察到什么现象?还能用串口打印出来吗?

<details>
<summary>答案</summary>

第一个拿到锁的任务打印完不放锁 → 第二个任务在 Take 处**永久阻塞**,打印从此只剩第一个任务在输出。

而且 printf 本身不依赖锁,所以**还能打印**(如果是第一个任务),只是"多任务打印"退化成"单任务打印"。

</details>

---

**Q3.** 为什么 fputc 内部加锁(Take/Give 每个字符)挡不住两行穿插?

<details>
<summary>答案</summary>

因为穿插发生在**两行之间** —— A 打一行时在 fputc 内部频繁取放锁,B 的字符照样能插进 A 行中间(每字符都是合法临界区)。

锁的粒度必须匹配"一整行"这个原子单位。

</details>
