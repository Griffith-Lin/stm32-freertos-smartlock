# I2C 通信与推挽/开漏选型

> 一句话定位:**I2C 的两条线天生是"线与"总线 → 必须开漏 + 上拉;推挽只属于"这条线只有我一个人驱动"的场合。**
> 判断口诀:**一条线上会不会有第二个器件也来驱动它?会 → 开漏;只有我说了算 → 推挽。**

---

## 1. 先看电学本质:推挽和开漏到底是什么

### 1.1 推挽(Push-Pull,`GPIO_OType_PP`)

```
              VCC
               │
            ┌──┴──┐
            │ P-MOS│   ← 上管
      输出 ─┤      ├──● 引脚
            │ N-MOS│   ← 下管
            └──┬──┘
               │
              GND
```

- 输出 **1** → 上管导通,引脚被**主动接到 VCC**(强驱动高)
- 输出 **0** → 下管导通,引脚被**主动接到 GND**(强驱动低)

两个方向都主动驱动,一个"推"上去、一个"挽"下来,所以叫推挽。

### 1.2 开漏(Open-Drain,`GPIO_OType_OD`)

```
        (上管不存在 / 永久关断)

      输出 ──┤ N-MOS 漏极 ──● 引脚
              │
             GND
```

- 输出 **0** → 下管导通,引脚被拉到 GND
- 输出 **1** → 下管关断,引脚**高阻(悬空)**,它什么都不做

开漏**只能拉低,不能拉高**。"开漏"= 漏极开路,输出 1 时引脚处于"松手"状态。

⚠️ **关键推论:开漏输出的高电平不是芯片给的,是外部上拉电阻给的。**
没有上拉电阻,这条线的"1"就是高阻悬空 —— 既不是高也不是低,一碰就乱跳。

STM32 里对应 `GPIO_OType_PP` / `GPIO_OType_OD`,落到寄存器是 `GPIOx_OTYPER` 的对应位:**0 = 推挽(复位默认值),1 = 开漏**。

---

## 2. 为什么 I2C 必须开漏:线与(Wired-AND)

I2C 总线上挂的所有器件,**每一个都只能拉低**。于是:

```
        VCC
         │
        ┌┴┐ 上拉电阻
        └┬┘
         │
    ─────┼─────●───────●─────   SCL/SDA
         │     │       │
      [主机]  [从机A]  [从机B]
      只能拉低  只能拉低  只能拉低
```

线电平 = **所有器件里最低的那个**。只有**所有**器件都松手,线上才是高电平 —— 这就是**线与**。

由此推出 I2C 三大机制全都建立在开漏之上:

| 机制 | 怎么靠开漏实现 |
|---|---|
| **应答 ACK** | 主机发完 8 位后**松手**,从机把 SDA 拉低 = ACK;松手 = NACK |
| **多主仲裁** | 两个主机同时发,谁发 0 谁赢(发 1 的那个发现线是 0,自己退出) |
| **时钟拉伸** | 从机拉低 SCL 让主机等着,主机也只能松手后才看到高 |

**任何一个环节换成推挽,这套机制立刻崩掉。** 最典型的是 ACK:SDA 上如果主机推挽输出高、从机拉低回应答,就是两个 MOS 管直接对顶。

## 3. 选型表:什么场合用哪个

| 场合 | 输出模式 | 为什么 |
|---|---|---|
| **I2C 的 SCL / SDA** | **开漏** | 线与总线,必须允许别人拉低 |
| SMBus / PMBus | 开漏 | 同上 |
| 1-Wire(DS18B20) | **开漏** | 单线双向 + 寄生物供电 |
| 电平转换(3.3V ↔ 5V) | **开漏** | 见 §6 |
| SPI 的 SCK / MOSI / CS | 推挽 | 每条线只有主机驱动,从机只收不发 |
| UART TX | 推挽 | 单向,发送方独占 |
| 复位脚(如 CY9CM 的 RES) | 推挽 | 单向控制,要主动驱动高**和**低 |
| PWM 驱动 LED / MOSFET 栅极 | 推挽 | 需要快速边沿 + 强驱动 |

判断本质就一句话:**这条线上有几个驱动者?**
一个 → 推挽(快、强、省心);两个及以上 → 开漏(不然一定对顶)。

## 4. 配错会怎样(最常被问的问题)

### 4.1 该开漏却配成推挽 → **对顶**,最危险

**对顶 = 两个 MOSFET 同时导通,把 VCC 和 GND 直接接通。**

#### ① 发生在哪个时刻:从机拉伸时钟的那一瞬间

从机"拉伸时钟"的动作是:**把自己的 SCL 引脚拉低并保持住**,意思是"等会儿,我还没准备好"。

主机是开漏的话,这时它只是在"松手",谁也不较劲:

```
开漏主机:  N-MOS 关断, 引脚高阻     ← 什么都不做
从机:      N-MOS 导通, 线被拉到 GND
结果:      线 = 低, 电流只有上拉电阻那 0.7mA, 相安无事
```

主机是推挽的话,它到点了要"发出高电平":

```
   3.3V                                    3.3V
    │                                        │
  ┌─┴─┐ P-MOS 导通                        ┌─┴─┐ 上拉电阻 4.7k
  │   │ ─► 约 50Ω                         └─┬─┘ (此时完全没用了)
  └─┬─┘                                     │
    ●──────────── SCL 走线 ────────────────●
    │                                        │
  ┌─┴─┐ N-MOS 关断                       ┌─┴─┐ N-MOS 导通
  │   │                                  │   │ ─► 约 50Ω
  └─┬─┘                                  └─┬─┘
    │                                       │
   GND                                     GND

   →  3.3V ─[P-MOS]─[走线]─[N-MOS]─ GND   一条直路
```

**两个管子同时导通,VCC 和 GND 之间只剩它们的导通电阻。** 这就是总线竞争(bus contention)。

#### ② 电流有多大

```
I = 3.3V / (50Ω + 50Ω + 走线) ≈ 30 mA 量级
P(单管) = I² × R = 0.03² × 50 ≈ 45 mW
```

对比 STM32F401 的绝对最大额定值:**单 I/O ±25 mA,所有 I/O 合计 120 mA**(以数据手册为准)——**对顶瞬间就已经超规**。

45mW 看着不大,但它灌在一颗只有几百 µm² 的 MOSFET 里,而且**只要从机还在拉伸就一直流**——拉伸几十毫秒是常事(EEPROM 写周期、传感器转换都会拉伸)。

#### ③ 从"超规"到"烧",中间隔着闩锁

**路径一:直接过流。** 持续超规 → 输出级铝走线电迁移、结温升高 → 慢慢劣化乃至熔断。要持续一段时间,一般不会瞬间死。

**路径二:CMOS 闩锁(latch-up),这才是"烧引脚"最常见的死法。**

CMOS 工艺里,PMOS 的源/漏 + N 阱 + P 衬底天然构成寄生 PNP,N 阱里又有一个寄生 NPN,两者首尾相接 = 一个**可控硅(thyristor)**:

```
   正常:  寄生可控硅截止,不导通
   大电流注入衬底 → 触发 → 可控硅自锁导通 → 只能断电解除
```

一旦触发,**即使外部对顶条件消失,它也会自己维持导通** —— VCC 到 GND 变成几十欧的低阻通路,电流从几十 mA 飙到几百 mA。这时芯片是真的在冒烟,而且**软件复位救不回来,只能断电**。

对顶产生的正是"大电流注入衬底"这个触发条件。所以工程上的说法是:**对顶不一定会烧,但它在给闩锁创造条件,而这个条件一旦满足就是不可逆的。**

#### ④ 有一个 100% 会发生的后果,不用等烧

对顶时那条线的电压是两颗管子分压出来的:

```
V = 3.3V × 50Ω/(50Ω+50Ω) ≈ 1.65V
```

3.3V CMOS 输入判 0 门限约 1.0V、判 1 门限约 2.0V,**1.65V 正好卡在死区** —— 读成 0 还是 1 全看噪声和个体差异。

所以对顶时从机看到的时钟是"在乱跳",通信结果随机。**这个后果立刻发生、必然发生;烧引脚反而是概率性的。**

#### ⑤ 为什么开漏天生免疫

| 主机想输出 | P-MOS | N-MOS | 引脚状态 |
|---|---|---|---|
| 高(写 1) | **根本不存在** | 关断 | 高阻(松手) |
| 低(写 0) | 不存在 | 导通 | 拉到 GND |

**开漏只有下拉能力,没有上拉能力。** 从机拉低时,主机即使"想输出高"也只是松手,没有任何东西在和从机较劲。这就是 I2C 规定 SCL/SDA 必须开漏的根本原因 —— **不是风格偏好,是"线与"总线的硬性要求。**

#### ⑥ 排查现象

- 通信时好时坏、读回值随机
- 芯片发烫、电流表读数异常偏大(正在对顶时)
- 严重时引脚永久损坏,之后怎么配都不通

⚠️ 对顶是"**有条件才发作**"的:只有总线上真的出现第二个驱动者时才会发生。所以它可能在你桌上跑几天都没事,到现场接了第二个器件就炸 —— **这种"埋伏型"故障比立刻坏掉更难查**。这也是 §4.3 说的那种"配错了但恰好能跑"的危险所在。

### 4.2 该推挽却配成开漏 → 没有上拉就永远出不来高电平

- **没有外部上拉**:输出 1 时引脚高阻 → 线永远回不到高 → 从机一个字节都不应答 → **地址相位一直 NACK / 每次读回全 0**
- **有上拉但阻值太大**:边沿变软,低速勉强能用,提速后数据还没建立就被采样 → 随机错误
- **有上拉但忘了预置 ODR**:见 §5.1

### 4.3 最阴险的一种:配错了,但**恰好没出问题**

总线上如果"应该对顶"的两个驱动者,当前恰好只有一个在动,推挽就能跑通。**"能跑"不等于"配对了"**,它只说明当前这个场景恰好没踩到。

本工程就撞上了这种情况,实测记录见 §7。

## 5. 四个容易翻车的细节

### 5.1 GPIO_Init 之前必须先把 ODR 预置成 1

GPIO 复位后 `ODR = 0`。如果直接 `GPIO_Init` 成输出,引脚**在配置生效那一瞬间就开始输出低电平**:

```c
// i2c.c 里这两句不能删
I2C_SDA = 1;   // 先"松手"
I2C_SCL = 1;   // 再切输出
```

否则上电瞬间 SCL/SDA 同时被拉低,在从机看来是一个非法的"总线忙 + 起始条件",有的从机会直接锁死。

### 5.2 读 SDA 之前必须先写 1(释放)

`i2c_master_read()` 第一句是 `I2C_SDA = 1;` —— 开漏下这句是"松手"而不是"驱动高"。忘了它,主机把 SDA 按在低电平上,从机想拉多低都没意义,**读回来永远是 0**。

### 5.3 为什么配成输出还能读回来

```c
GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_7)   // PB7 此时是"输出"模式
```

这在 STM32 上是合法的:**IDR(输入数据寄存器)每个 APB 时钟周期都会采样引脚的实际电平,跟引脚配成输入还是输出无关**,只有模拟模式会关掉施密特触发器。

这正是软件 I2C 能"同一条线又写又读"的硬件基础 —— 写靠 ODR 控制开漏管,读靠 IDR 看线电平。

### 5.4 GPIO_PuPd 什么时候开内部上拉

| 场景 | 选 |
|---|---|
| 从机侧 / 纯输入脚(按键等) | 开内部上拉,省一颗电阻 |
| **主机侧、外部已有上拉** | **`GPIO_PuPd_NOPULL`** |
| 想用内部弱上拉顶替外部上拉跑 I2C | **别这么干** |

STM32 内部上拉典型值 **40kΩ**。和外部 4.7kΩ 并联后是 4.2kΩ,对上升沿几乎没有帮助,反而在总线被拉低时多一条漏电通路。

而如果**只有** 40kΩ 内部上拉:配 100pF 总线电容,上升时间 ≈ `R×C = 40k×100p = 4µs`。一个位周期才多少?只能在极低速下勉强工作。

## 6. 开漏的一个免费福利:电平转换

3.3V 的 MCU 和 5V 的器件挂在同一条 I2C 总线上,**不需要任何电平转换芯片**:

```
              5V
               │
              ┌┴┐ 上拉电阻接到 5V
              └┬┘
    ───────────┼───────────  SDA
               │
      [3.3V MCU]      [5V 器件]
      开漏:只管拉低     只能拉低
```

高电平由 5V 上拉提供,低电平由任意一方拉低。MCU 引脚在输出 1 时是**高阻**,5V 灌不进来 → 安全。

⚠️ 前提两条:① **必须开漏**;② **该引脚得是 5V 容忍(FT)脚**。查数据手册确认,别想当然。

推挽做不到这一点:推挽输出高就是实打实的 3.3V,5V 器件可能识别不了;反过来 5V 器件推高还会往 MCU 引脚里灌电流。

## 7. 本工程实测记录(2026-09-14)

**硬件**:STM32F401 + CY8CMBR3116 触摸键盘,PB6 = SCL,PB7 = SDA,原理图确认两条线上**有**外部上拉电阻。

| SCL (PB6) | SDA (PB7) | 结果 |
|---|---|---|
| 推挽 PP | 开漏 OD | 按键读取成功 |
| **开漏 OD** | **开漏 OD** | **依旧成功 ← 最终采用** |

**结论**:两种配置都能跑通 → **SCL 配推挽不是之前那次通信失败的关键原因**。

回看那次 `FAIL 00000000 / 0x00`——一开始把 SCL 改成推挽,理由是"怀疑板上没上拉"。后来对原理图确认上拉确实存在,两种配置又都通,说明真正的病根在别处,见 [api/CY9CM.c](../api/CY9CM.c):

1. **CY8CMBR3116 处于低功耗态时会对地址回 NACK**,必须反复重发 `START + 地址` 直到收到 ACK(`cy9cm_wait_addr`)—— 这是数据手册要求的握手,不是故障;
2. 字节之间要留间隔(`CY9CM_BYTE_GAP_US = 500`);
3. 上电要给 RES 一个复位脉冲,芯片才从确定状态启动;
4. 读寄存器要分两段事务:写寄存器指针 → STOP → 重新 START 发读地址。

**方法上的收获**:遇到"没反应",第一反应不该是"网上抄的代码改一改试试",而是**先确认硬件事实**(翻原理图、万用表量上拉、示波器看波形),再按规范选参数。这次两种配置各烧一次板的时间,本来翻一眼原理图就能省掉。

## 8. 坑清单

| 坑 | 后果 |
|---|---|
| I2C 的 **SCL 配推挽** | 从机若拉伸时钟 → 对顶、大电流、可能烧引脚 |
| I2C 的 **SDA 配推挽** | 从机每次应答都在拉低 → **必然**对顶 |
| 开漏但**没有上拉电阻** | 线回不到高电平,从机全程不应答 |
| 开漏 + 忘了释放 SDA 就读 | 读回全是 0 |
| `GPIO_Init` 前没预置 `ODR = 1` | 上电瞬间把总线拉低,从机可能锁死 |
| 拿内部 40kΩ 上拉当外部上拉 | 边沿太软,稍提速就出错 |
| 外部已有上拉还开内部上拉 | 并联后阻值几乎不变,白增漏电 |
| 推挽直连 5V 器件 | 电平不匹配 + 反向灌流 |
| 配错了但"恰好能跑" | 埋雷:换个从机/加个器件就炸 |

2. 开漏输出写 1 时,引脚上是什么状态?这一位的高电平由谁提供?
3. `i2c_master_Config()` 里 `I2C_SDA = 1; I2C_SCL = 1;` 这两句,删掉会出什么问题?

<summary>答案(点开)</summary>

1. SDA 上有**两个驱动者**(主机 + 从机),从机要靠拉低 SDA 回应答,主机推挽就会和从机对顶。MOSI 只有主机一个驱动者,从机只收不发,永远不驱动这条线,所以推挽没问题。
2. **高阻(悬空)**,引脚不驱动任何电平。这一位的高电平由**外部上拉电阻**提供。
3. 这两句防的是"GPIO 复位(ODR=0)到第一次写 ODR 之间"的那个窗口。删了之后,`GPIO_Init` 一执行就立刻把 SCL/SDA 拉低,在从机看来是一个非法的"总线忙 + 起始条件",有的从机会锁死。**注意:即使总线有上拉,这两句也不能删** —— 上拉只能把线拉高,挡不住主机自己这个新出现的下拉。
4. 开漏:`I2C_SCL = 1` 是"松手",没有上拉就没人拉高 → **读到 0V**。推挽:芯片主动输出高 → **读到 3.3V**。所以这个实验就是**判断"外部上拉到底存不存在"**的办法:开漏量到 3.3V 说明上拉在;量到 0V 说明没有(或虚焊)。
5. 主机 P-MOS 推高、从机 N-MOS 拉低(比如正在回应答),VCC → P-MOS → N-MOS → GND 直通,电流只受两个管子导通电阻限制,所以异常大。
6. **不需要**。上拉电阻接到 5V,MCU 开漏只负责拉低(输出 1 时高阻,5V 灌不进来),高电平由 5V 上拉提供。前提是**用开漏**且**该引脚是 5V 容忍(FT)脚**。
