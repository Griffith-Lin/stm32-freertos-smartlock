# NV400F 语音模块:音频烧录的完整流程与踩坑记录

> 一句话定位:**"烧录软件显示成功"≠"音频真的进了芯片"。**
> 这次"一声不响"是两个独立故障叠在一起:代码延时算错 + 音频压根没烧进去。
> 排掉一个还有一个,这也是它绕了这么久的原因。

---

## 1. 故障现象与两个独立原因

**现象**:官方软件显示烧录完成,MCU 也在按协议发命令,但模块一声不响。

事后复盘,链路上有**两个各自独立、都能单独导致静音**的故障:

| # | 故障 | 性质 | 怎么发现的 |
| --- | --- | --- | --- |
| ① | `Delay_Us()` 按 168MHz 标定,实际跑在 84MHz | **代码 bug** | 反汇编数循环:168 个 NOP + 5 周期开销 = 173 周期,173/84MHz = **2.06µs** |
| ② | 音频根本没烧进芯片 | **操作/流程问题** | 按标准流程重烧一遍就好了 |

### ① 位宽为什么会翻倍

`delay.c` 里那行注释是破案的关键:

```c
// 实际时间：198×5.95ns≈1178ns
```

**5.95ns 正好是 1/168MHz** —— 这个函数是给 168MHz 的片子标定的。搬到 84MHz 的 F401 上,每个"微秒"实际是 2.06µs:

| | 协议要求 | 改之前实际 | 改之后 |
| --- | --- | --- | --- |
| 起始低电平 | 3~9ms | **10.3ms** ❌ | 5ms ✅ |
| bit'1' | 高1200 + 低400 | **高2471 + 低824** ❌ | 高1200 + 低400 ✅ |
| bit'0' | 高400 + 低1200 | **高824 + 低2471** ❌ | 高400 + 低1200 ✅ |

**注意这里最坑的一点**:高低电平的**比例**始终是 3:1,完全正确。但本协议对**绝对宽度**也有要求(手册推荐 100:300 ~ 400:1200µs),整体翻倍就超出范围了。

> **教训**:碰到"比例对但就是不通"的时序协议,一定要量绝对时间,不能只看占空比。

修法是改用硬件计数器,不再数 NOP:

```c
void NV400F_DelayUs(uint32_t us)
{
    uint32_t prev = TIM10->CNT;      // TIM10 被配成 1us 一跳、数到 999 归零
    uint32_t acc  = 0;

    while (acc < us)
    {
        uint32_t now  = TIM10->CNT;
        // now < prev 说明两次读之间绕过了一次 0
        uint32_t step = (now >= prev) ? (now - prev) : (1000u + now - prev);
        acc += step;
        prev = now;
    }
}
```

好处:不受主频、优化等级、Flash 等待周期影响。**而且中断插进来也不会算错** —— 它量的是真实流逝的时间。手册虽然要求发码期间关中断,但这个写法对中断抖动天然免疫,不用真去关。

> 前提:`TIM10_Task_Config(84, 1000)` → `PSC=83`、`ARR=999`,APB2 预分频为 1 所以 TIM10 时钟 = 84MHz,
> 分频后正好 1MHz → **CNT 1µs 一跳、1000 计数一周期**,和按模 1000 累加的假设严丝合缝。

### 另一种修法:把 NOP 数改对

不想依赖 TIM10 的话,直接按新主频重新数 NOP 也行 —— 原来 **168 个**,改成 **84 个**(正好一半):

```c
void Delay_Us(u32 ustime)
{
    while(ustime--)
    {
        __NOP();  × 84      // 84 个 NOP ≈ 84 个周期 @84MHz
    }
}
```

**但循环本身也有开销,不能只数 NOP。** `while(ustime--)` 在 -O0 下编成 3 条指令:

```asm
loop:
    subs  r1, r0, #0     ; 1 周期
    sub.w r0, r0, #1     ; 1 周期
    bne.w loop           ; 跳转要冲流水线,约 3 周期
```

所以单次迭代 = **NOP 数 + 约 5 个周期**:

| 版本 | NOP 数 | 总周期 | @84MHz 实际 |
| --- | --- | --- | --- |
| 旧(168MHz 标定) | 168 | 168 + 5 = **173** | **2.06µs** ❌ |
| 新(84MHz 标定) | 84 | 84 + 5 = **89** | **约 1.06µs** |

改完仍然偏长 **6%** —— 因为那 5 个周期的循环开销没法靠减 NOP 消掉。

> 6% 对 NV400F 完全够用(bit'1' 高电平 1200µs → 约 1271µs,仍在手册推荐的 400:1200 内)。
> 但**要求严格 1µs 的场合得把这 5 个周期扣掉**,也就是写 **79 个** NOP 而不是 84 个。

**两种修法怎么选:**

| | 数 NOP(84 个) | 读 TIM10 计数器 |
| --- | --- | --- |
| 精度 | 受主频、优化等级、Flash 等待周期、编译器版本影响 | 只取决于 TIM10 时钟 |
| 中断插进来 | **直接变长**,算错 | 天然免疫,量的是真实流逝的时间 |
| 换主频 / 换芯片 | 必须重新数一遍 | 不用改 |
| 一眼看懂 | 84 个 NOP 看不出是 1µs | 函数名就写着 |
| 额外开销 | 无 | 几次寄存器读 |

> 像 WS2812 那类驱动普遍用数 NOP,是因为它把整条时序链的周期数都自己攥着,而且**通常关中断**。
> NV400F 这里中断是开着的(TIM10 和 SysTick 都在跑),所以计数器版本更稳 —— 这也是最终选它的原因。
>
> ⚠ **改 NOP 数前先想清楚优化等级**:`-O0` 下 `__NOP()` 一条就是一条;
> 一旦开 `-O2`,编译器可能把连续 NOP 合并、或者把整个循环优化掉,数出来的周期全废。
> 本工程固定 `-O0`,所以暂时安全。

### ② 烧录失败的教训

软件报"成功"不等于芯片里真有音频。**判据应该是"上电后能不能放出来",而不是"软件弹没弹成功框"。**

## 2. 为什么烧录前必须注释掉 `NV400F_Init()`

这是整个流程里最容易忽略、也最必须的一步。

```c
void NV400F_Init(void)
{
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_OUT;   // ← PC5 被配成推挽输出
    GPIO_Init(GPIOC, &GPIO_InitStruct);
}
```

烧录音频时,**模块的 DATA 线要由 USB 转 TTL 来驱动**。可如果 MCU 还在跑,PC5 是个**推挽输出** —— 它有自己的强驱动能力,会和 USB 转 TTL 的输出**对着干**:

```
    MCU(推挽输出高) ──┬── NV400F DATA
                      │
    USB转TTL(想拉低) ──┘   ← 两个输出顶牛,线上电平不确定
```

轻则数据收错、烧录失败,重则长时间对顶烧掉引脚。

**注释掉 `NV400F_Init()` 之后,PC5 保持复位默认值 = 浮空输入**,MCU 相当于从那根线上"松手"了,线由 USB 转 TTL 独占。

> 所以顺序是:**先改代码 → 重新构建 → 烧录 MCU → 再做模块的音频烧录**。
> 不是"先烧音频再改代码"。

## 3. 烧录流程(按顺序)

| 步骤 | 操作 | 要点 |
| --- | --- | --- |
| 1 | 注释 `NV400F_Init()`,重新构建并烧录 MCU | 让 PC5 变成浮空输入,从 DATA 线上松手 |
| 2 | **拨码开关断电** | 先断电再改接线,不要带电插拔 |
| 3 | 给 **PWMN 口接上跳线帽(接地)** | 拉低这个脚 = 芯片下次上电进**下载模式** |
| 4 | 拨码开关切到 **USB 转 TTL ↔ NV400F 的 TX/RX** | 串口从 MCU 那边切到语音模块这边 |
| 5 | **先在软件里点"开始下载"** | ⚠ 顺序关键:先让软件开始握手 |
| 6 | **再拨动拨码开关给模块供电** | 上电瞬间抓住握手,进 bootloader |
| 7 | 等音频下载完成 | —— |
| 8 | 把串口切到 **460800**,发送**激活帧** | 模块规定波特率,帧见下 |
| 9 | **拔掉 PWMN 的跳线帽** | 解除下载模式,下次上电正常跑 |
| 10 | 拨码开关切回 **USB 转 TTL ↔ USART1** | 恢复 printf 控制台 |
| 11 | **重新上电,电源和烧录器都要拔掉** | 完整冷启动 |

### 第 8 步的激活帧

```
7E A5 5A 02 02 01 02 00 02 0F 01 00 08 02 EF
```

- **波特率必须是 460800**(模块规定,不是 115200)
- 固定 **16 字节**,`7E` 是帧头、`EF` 是帧尾
- 中间是厂家固化的载荷,**照抄即可,不要自己改任何一个字节**

## 4. 每一步背后的原理

### 拨码开关在切换什么

板子上其实只有**一个** USB 转 TTL,靠拨码开关在两个目标之间二选一:

```
        ┌──────────────┐
        │ USB 转 TTL   │
        └───────┬──────┘
                │  拨码开关在这里二选一
        ┌───────┴────────┐
        ↓                ↓
   MCU 的 USART1     NV400F 的 TX/RX
   (printf 控制台)    (烧录音频 / 发激活帧)
```

- 平时拨到 USART1 —— 看打印、调程序
- 烧音频时拨到 NV400F —— 让 PC 直接跟语音模块对话

### PWMN 接地 = 进入下载模式

这是典型的**启动模式选择脚**(boot strap):芯片在**上电复位的那一刻**采样这个引脚,

- **接地(低)** → 进 bootloader,等 PC 通过串口把音频传进来
- **悬空/拉高** → 直接跑 flash 里已经烧好的音频

所以它**必须在上电前就接好** —— 上电那一刻没采到,后面再接就晚了,只能重新上电。

### 为什么"先点下载,再上电"

bootloader 的握手窗口通常**只在复位后的很短时间内打开**。如果先供电、后点下载,等你手点下去的时候,芯片早就跑过那个窗口、进正常模式了。

正确做法是让 PC 端**先开始一直发握手**,这样模块一上电,bootloader 睁眼就能抓到。

> 这是很多串口 bootloader 的通用套路:**"让请求方先等着,再给目标上电"**。
> 和第 3 节的"必须在上电前接好 PWMN"是同一个道理 —— 都是**开机瞬间的采样/握手窗口**决定的。

### 拔 PWMN 跳线帽

解除下载模式的绑定。不拔的话,下次上电又进 bootloader,模块还是不出声。

### 为什么电源和烧录器都要拔

- **电源**:要的是完整冷启动,让芯片重新采样 PWMN、重新装载音频。
- **烧录器(CMSIS-DAP)**:SWD 口上一般接着 3.3V 和若干 IO。只拔电源不拔它,板子可能通过 SWD 的 3.3V 被**半供电**,或者 IO 上的保护二极管漏电过去,MCU 处于"半死不活"的状态,复位不完全。**要断电就断干净。**

## 5. 检查清单

烧完还是不响的话,按这个顺序查:

| 顺序 | 检查项 | 说明 |
| --- | --- | --- |
| 1 | 烧录**真的**成功了吗 | 别信软件的成功框,重点看模块上电后放不放得出来 |
| 2 | 控制方式是不是"**一线串口**" | 芯片同一时刻只有一种方式生效,选错了发什么都没反应 |
| 3 | PWMN 跳线帽拔了吗 | 没拔 = 一直在下载模式 |
| 4 | 激活帧发了吗 | 不发激活帧,音频可能还在暂存区没生效 |
| 5 | **共地**了吗 | MCU 和语音模块必须共地 |
| 6 | 模块供电是否 **≤ 4.7V** | 手册要求 `U(MCU) ≥ 0.7 × U(语音芯片)`,3.3V 的 MCU 配 5V 模块,高电平够不到阈值 |
| 7 | 位宽对不对 | 见第 1 节,量绝对时间而不是只看比例 |

## 6. 一句话总结

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| 位宽整体翻倍 | 延时按 168MHz 标定,实跑 84MHz | 改用 TIM10 硬件计数器计时;或把 NOP 数减半(168→84) |
| 数了 NOP 还是不准 | 漏算了循环本身的约 5 个周期开销 | 要严格 1µs 就扣掉开销,写 79 个 |
| 软件说成功、芯片里没音频 | 烧录流程不对 | 严格按第 3 节顺序重烧 |
| 烧录时数据收错 | MCU 的推挽输出和 USB 转 TTL 对顶 | 先注释 `NV400F_Init()`,让 PC5 浮空 |
| 上电就进下载模式 | PWMN 跳线帽没拔 | 烧完拔掉 |
| 死活连不上 bootloader | 握手窗口在上电瞬间 | **先点下载,再上电** |

**调试一条链路时,要能分别验证每一环 —— 这次就是两个独立故障叠在一起,"改了一个还不行"不等于"改错了",而是"还有一个没找到"。**
